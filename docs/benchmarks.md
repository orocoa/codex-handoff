# 性能测量

测量日期 2026-09-29，macOS 27 / arm64，Python 3.9.6；同机对比 alpha.16 与 alpha.17。系统文件缓存已预热或未受控。这些是合成本地测试，**不是整次交接或模型延迟基准**；没有测量 CPU 占用、峰值内存和能耗。

## 本地函数

每版本每场景 5 次，取中位数。

| 场景 | alpha.16 | alpha.17 | 含义 |
|---|---:|---:|---|
| 100 个保存目录中定位 | 811.47 ms | 13.19 ms | Git 调用次数 100 → 1 |
| 已创建请求的相同输入重试 | 2.80 ms | 1.49 ms | `fsync` 同步调用次数 10 → 5 |
| 10,000 条目录记录中的已登记记录重试 | 65.29 ms | 25.70 ms | 减少 JSON 序列化与写入 |
| 首次准备 | 4.60 ms | 5.00 ms | 没有加速 |

10,000 条记录的目录夹具预置的是旧快照元数据，并未生成 10,000 份完整交接包。它衡量目录处理成本，不证明整个档案的一致性。重复测量结果会随机器负载、存储、路径布局和数据结构变化。

## 日志检查

使用实际已安装的 alpha.17 代码。每版每尺寸交替运行 3 个新 Python 进程，以下为中位数；alpha.17 首次运行另测 1 次。新进程**不等于**冷磁盘测试。

| 合成日志 | alpha.16 | alpha.17 后续运行 | alpha.17 首次运行 |
|---|---:|---:|---:|
| 1 MiB | 34.49 ms | 40.10 ms | 39.15 ms；无扫描缓存 |
| 128 MiB | 443.13 ms | 96.77 ms | 521.99 ms；建立缓存 |

各次运行的压缩次数、坏行数和未完成尾行判断一致。大日志缓存命中有收益；小日志与首次建立大日志缓存没有收益。4 MiB 以下跳过扫描缓存；大日志启用状态时仍会读取并哈希旧前缀，只减少重复 JSON 解码。因此读取成本仍是 O(总字节数)，不是 O(追加字节数)。

## 文本体积与验证

- `SKILL.md`：6,741 → 5,595 字节，入口文件字节数约减少 17%。
- 合成案例中的接收提示：1,160 → 1,036 字节。
- 该案例推荐命令的 CLI 输出：2,096 → 1,992 字节。
- 安装后的版本：**133 项测试通过**，失败、错误与跳过均为零。

文本字节数不是测得的模型词元数或计费成本，本项目不据此声称端到端延迟下降。仓库测试覆盖功能回归与模拟协议服务，不等同于复现此处性能测量。

## 保留的本地测量 — 2026-10-14

首轮审查在同一台 macOS、Python 3.9.6 上对比基线与候选快照，使用合成本地文件；新旧版本交替运行。未变日志检查每版函数 10 次、CLI 5 次；首次准备每版 5 次，以下取中位数。数据早于第二轮最终元数据与错误处理修复，不是 alpha.18 新发布压缩包的基准。

| 场景 | 基线 CLI | 候选 CLI | 含义 |
|---|---:|---:|---|
| 完全未变 64 MiB 日志命中缓存 | 81.09 ms | 41.63 ms | 复用精确文件版本 |
| 无历史的首次准备 | 106.71 ms | 106.92 ms | 未加速 |
| 1,000 条历史记录的首次准备 | 81.86 ms | 86.85 ms | 未加速 |

完全未变文件的快速路径校验 `device`、`inode`、`size`、`mtime`、`ctime`，并在复用前再次核对打开文件与路径。追加、替换、截断或修改仍走前缀核验或全扫描回退；4 MiB 以下仍跳过缓存。第二轮未修改这项实现。样本中的首次准备没有提速，内联上下文的模型与工具成本未测量。

最终源码通过 180 项本地回归及 11 个接续情景；两轮编排共通过 32 次模拟分支检查，验证两轮调用流程可执行；独立模型接收者试用验证了本地来源路径与最新决定。没有在侧栏创建真实交接对话，也未测量整次交接、宿主启动或模型延迟。主文更短、工具边界更少，不能据此推出端到端提速百分比。
